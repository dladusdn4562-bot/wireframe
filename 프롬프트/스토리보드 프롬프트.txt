[스토리보드 제작 - 클라이언트별 메인 생성 & 최종 3장 마스터 병합 프롬프트]

현재 작업 폴더를 기준으로 아래 작업을 수행해줘.

================================================================================
1. 작업 환경 및 입력·참조 파일 체계
================================================================================
- 사이트맵 입력 파일: [가상클라이언트 설계 결과\설계 출력물\사이트 구조맵\사이트맵_가상클라이언트_{N}_*.md]
- 서비스 흐름도 입력 파일: [가상클라이언트 설계 결과\설계 출력물\서비스 흐름도\서비스_흐름도_{N}.md]
- 화면 설계서 입력 파일: [가상클라이언트 설계 결과\설계 출력물\화면 설계서\화면_설계서_{N}.md]
- 추가 분석 참고 파일: [가상 클라이언트 모음\사이트 분석 결과\사이트분석결과_가상클라이언트_{N}_*.md]
- 제외 사항 기준 파일: [스토리보드 제외 사항.txt]
- 결과물 저장 폴더: [가상클라이언트 설계 결과\설계 출력물\스토리보드 결과]

================================================================================
2. 작업 목표 및 단계별 원칙
================================================================================
1) **클라이언트별 개별 스토리보드 생성**: 각 가상클라이언트(Client 1, 2, 3... N)는 분할할 필요 없이 해당 클라이언트의 타깃 페르소나에 집중된 **[메인페이지 스토리보드 (`메인페이지_스토리보드_{N}.md`)]**를 클라이언트 수만큼 최대한 많이 전수 생성할 것.
2) **최종 마스터 스토리보드 3장 종합 병합**: 모든 클라이언트의 설계가 누적 완료된 후, 전 클라이언트의 다양한 요구와 분석 데이터를 종합 집대성하여 **[메인페이지 1장 + 카테고리 1장 + 브랜드 소개 1장]**으로 구성된 최종 1개의 마스터 완결본 **[`스토리보드_마스터.md`]**를 병합 생성할 것.

- 별도의 HTML 시각화 파일은 생성하지 않고, CLI 환경 및 마크다운 뷰어에서 즉시 검토하고 타 도구로 연계 가능한 단일 마크다운(`.md`) 및 데이터(`.json`) 파일로 제작할 것.
- 모든 산출물은 단순형 번호 접미사(`_{N}`) 및 마스터(`_마스터`)를 부여하고 UTF-8 인코딩으로 생성할 것.

================================================================================
3. 생성할 산출물 목록 및 상세 구성
================================================================================

[A] 클라이언트별 개별 산출물 (클라이언트 수만큼 전수 생성)
1. `메인페이지_스토리보드_{N}.md`
   - 클라이언트 {N} 맞춤형 메인페이지 전체 레이아웃 구조도 (ASCII 와이어프레임)
   - 클라이언트 {N} 타깃 중심 14개 섹션 및 연계 모달별 1:1 표준 상세 표
2. `스토리보드_목록_{N}.json`
   - 클라이언트 {N} 메인페이지 섹션 표준 JSON Schema

[B] 전체 클라이언트 최종 종합 마스터 산출물 (최종 1개 완결본)
1. `스토리보드_마스터.md` (전 클라이언트 데이터 집대성 3장 완결본)
   - **[1장] 통합 메인 랜딩페이지**: 전 클라이언트 페르소나(직장인, 수험생, 개발자 등)의 유입 동선과 가치 제안이 통합된 마스터 메인 표
   - **[2장] 통합 카테고리 페이지**: 모든 타깃 부위(어깨/거북목, 척추/허리, 골반/하체) 제품 및 정밀 사이즈 매칭이 통합된 마스터 카테고리 표
   - **[3장] 통합 브랜드 소개 페이지**: Effort-Free 웰니스 비전, 전 원천기술, 공인 시험성적서/특허, R&D 검증이 집대성된 마스터 브랜드 스토리 표
2. `스토리보드_마스터_목록.json`
   - 3개 핵심 페이지 전체 섹션 통합 JSON Schema

================================================================================
4. 각 화면/섹션당 1:1 표준 표(Table) 필수 항목 (11개 규격)
================================================================================
모든 화면의 각 섹션은 반드시 아래 11개 항목을 포함한 정형화된 마크다운 표로 작성할 것:
1. 화면 ID / 화면명 / 뎁스 / 섹션 코드 및 명칭
2. 화면 목적 및 사용자 핵심 목표 (User Goal)
3. 주요 콘텐츠 및 카피라이팅 (헤드카피, 서브카피, 본문 안내문구, 배지)
4. 인터페이스 및 UI 요소 (버튼, 입력창, 탭, 슬라이더, 셀렉트박스 등)
5. 레이아웃 및 컴포넌트 배치 (헤더, 히어로, 바디 그리드, 사이드, 푸터)
6. 작동 방식 및 사용자 인터랙션 (클릭, 호버, 스크롤 인터랙션, 상태 전환)
7. 연결 화면 및 이동 링크 경로 (Target Screen ID 매핑)
8. 사용자 여정 경로 (User Journey Step: ST-01~ST-92 매핑)
9. 화면 상태별 UI 명세 (기본, 로딩, 빈 상태, 오류, 완료)
10. 반응형 레이아웃 기준 (데스크톱 ≥1200px, 태블릿 768~1199px, 모바일 ≤767px)
11. 비고 및 기획 의도 주석 (UX 기획 배경)

================================================================================
5. 엄격한 제외 사항 (Exclusion Rules: 스토리보드 제외 사항.txt 반영)
================================================================================
아래의 항목은 스토리보드 본문 및 JSON 산출물에 절대 포함하지 않고 완전히 제외할 것:

1. **HTML 시각화 파일 생성 제외**: 별도의 HTML 와이어프레임 시각화 파일은 생성하지 않음.
2. **웹 접근성 전용 요구사항 및 명세표 제외**:
   - 구조적 랜드마크(header/nav/main/section/footer), 본문 바로가기 스킵 내비게이션
   - 이미지 대체 텍스트(alt) 정책, 키보드 단독 조작, 포커스 인디케이터/가림 방지
   - 명도 대비(4.5:1 / 3:1), 비색상 정보 전달, 모션 감소(prefers-reduced-motion) 제어
   - 모바일 터치 타깃(44x44px), 오류 스크린리더 연결, 200%/320px 확대 대응, 동적 라이브 영역(aria-live) 등
3. **가정 사항 및 확인 필요 사항 명세표 제외**:
   - 로그인/마이페이지 인증 정책 가정, 반응형 분기점(1280/768/360px) 가정, UI 채택 가정
   - 통계 원출처/표본 확인, 제품/이미지 가이드 수급, AI 점수 산식 연동, 제휴센터 DB 확정, 후기 초상권 동의, 30일 무료체험 법무/반품 조건, 회사 정보 확정, 의료적 효능 법무 검토 등 확인 필요 사항 명세표

================================================================================
6. 작성 규칙 및 품질 검증 기준 (Quality Gate)
================================================================================
- **화면명 및 ID 동기화 (100%)**: 사이트맵(`P-0.0`, `P-1.0`, `P-2.0`), 서비스 흐름도(`ST-01` ~ `ST-92`), 화면 설계서(`SCR-01`, `SCR-02`, `SCR-03`)의 모든 명칭과 화면 ID를 오차 없이 일치시킬 것.
- **다수 클라이언트 데이터 집대성 무결성**: 개별 메인 스토리보드(`메인페이지_스토리보드_{N}.md`)가 온전히 축적된 후, 마스터 스토리보드(`스토리보드_마스터.md`)에서 다중 페르소나의 가치 제안이 3장 구조로 충돌 없이 유기적으로 병합되었는지 검증할 것.
- **문법 및 무결성 검증**: JSON 파일의 스키마 유효성 및 UTF-8 인코딩을 검증하고, 마크다운 표 깨짐이 없도록 정렬할 것.
- **완료 보고**: 작업 완료 후 생성한 파일의 상대 경로, 파일별 핵심 용도, 검증 결과를 간결하고 명확하게 출력할 것.
