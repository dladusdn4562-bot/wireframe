# 스킬 제목: [예: 시장 동향 리서치 수행]

이 Skill은 [어떤 데이터]를 바탕으로 [어떤 결과물]을 작성하는 데 목적이 있다. 
[주의: 스스로 결과를 승인하거나, 다음 단계의 파일을 미리 만들지 않는다.]

## 1. 사전 확인 및 입력 (승인 게이트)
- [어떤 파일(예: client-brief.md)]을 먼저 읽고 요구사항을 파악한다.
- 선행되어야 할 작업(예: 주제 선정 승인)이 완료되었는지 상태를 확인한다.
- 필수 파일이나 정보가 부족하면 무엇이 필요한지 사용자에게 알리고 작업을 중단한다.

## 2. 조사 및 분석 지침 (리서치 핵심 룰)
- **정보 출처:** [예: 정부 기관, 공식 문서 등 1차 자료를 우선하여 검색한다.]
- **팩트 체크:** 수치와 중요한 주장에는 반드시 교차 검증을 수행한다.
- **객관성 유지:** 확인된 '사실', 본인의 '해석', 데이터가 부족한 '가정'을 명확히 분리한다.
- **출처 표기:** 본문의 핵심 근거에는 [S01] 형식으로 출처 번호를 붙이고 하단에 링크를 명시한다.

## 3. 문서 작성 규칙 (포맷)
- [템플릿 파일 경로]의 필수 구조를 따른다.
- 경영진이나 실무자가 바로 읽고 이해할 수 있도록 결론을 먼저 서술한다.
- 불확실한 데이터나 검색되지 않는 정보는 임의로 지어내지 말고 '확인 필요'로 명시한다.

## 4. 파일 저장 및 상태 관리
- 생성된 결과물은 지정된 경로(`output/.../research-report.md`)에 저장한다.
- 기존 파일이 존재할 경우 덮어쓰지 않고 `archive/` 폴더에 타임스탬프를 붙여 백업한다.
- 작업 완료 후 전체 프로젝트의 상태 관리 파일(`workflow-status.md`)을 'draft' 상태로 업데이트한다.

## 5. 완료 전 자체 검증 (Checklist)
- [ ] 핵심 수치에 출처와 기준 시점이 누락되지 않았는가?
- [ ] 사실과 가정이 명확히 구분되어 있는가?
- [ ] 지정된 템플릿의 양식과 마크다운 형식을 준수했는가?
- [ ] 확인되지 않은 가짜 링크(Hallucination)가 포함되지 않았는가?

## 6. 최종 보고 (출력)
완료 후 다음 항목을 터미널(사용자)에게 보고하고 멈춘다.
- 생성된 파일의 경로
- 리서치의 핵심 발견점 (3줄 이내 요약)
- 정보가 부족했던 부분 (한계점)
- 사용자가 확인하고 승인해야 할 대상
